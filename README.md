```text
cDFT LAB
●─f₁₂─●∘
```
Our logo is a Mayer *f*-bond, $f_{12}=e^{-\beta u(r_{12})}-1$, with continuation into the many-body fluid.

Classical density functional theory (cDFT) & learned functionals for fluids.

- Physics-first: variational structure, nonlocality, reproducible numerics.
- Learning augments the baseline; it does not replace the physics.
- Focus: bridging particle and continuum scales.

## Reference
This repository is the companion code of

- E. Monti, P. Yatsyshin, K. Gkagkas, A. B. Duncan, *Hybrid physics-constrained learning of density functionals to bridge particle and continuum scales* (submitted to Communications Materials).

It contains the molecular dynamics (MD) reference data, the trained functional, and the scripts that train the functional from scratch and compute the planar adsorption profiles, the bulk liquid–vapour coexistence and critical point, the liquid–vapour surface tension, the three-dimensional droplets and the contact angles reported in the paper.

## Installation

### Requirements

- Python 3.10 or newer (tested with 3.12)
- A PyTorch build matching your hardware (CPU, CUDA, or Apple MPS)
- Packages listed in `requirements.txt`: `torch`, `numpy`, `pandas`, `matplotlib`, `tqdm`

A GPU is recommended for training (step 6), the 3D droplets (step 5) and the adsorption isotherms (step 7). Steps 2–4 and 8 run on a CPU.

### Setup

From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

pip install --upgrade pip
pip install -r requirements.txt
```

For CUDA or Apple MPS, install PyTorch from the [official install selector](https://pytorch.org/get-started/locally/) first if the default wheel from `requirements.txt` does not match your hardware, then install the remaining packages:

```bash
pip install numpy pandas matplotlib tqdm
```

### Running the scripts

**All scripts are run from `src/`**, so that `from libs...` imports resolve:

```bash
cd src
python <script>.py
```

Scripts are configured by constants at the top of the file (`WALL`, temperatures, solver parameters). The compute device is chosen automatically (CUDA, then MPS, then CPU); force one with

```bash
export TORCH_DEVICE=cpu    # or cuda | mps
```

and select a GPU on a multi-GPU machine with `CUDA_VISIBLE_DEVICES=<k>`.

Units are reduced Lennard–Jones units throughout (lengths in σ, energies in ε, T in ε/k_B).

## Step 1 — The data

### Planar adsorption profiles

NVT MD simulations of a Lennard–Jones fluid (truncated and shifted at r_c = 2.5) in a 60 × 20 × 20 box, with the wall at x = 0 and periodic lateral boundaries. `N` is the number of particles in the box; the profiles integrate to N/400 particles per unit wall area.

| Folder | Wall | External potential | N | T |
|---|---|---|---|---|
| `md_planar_wn2/` | V(1), training wall | LJ 9–3, ε_w = 1.2, σ_w = 1.2 | 8000 | 0.55, 0.60, …, 1.00 |
| `md_planar_wc/` | V(2) | LJ 9–3, ε_w = 1.0, σ_w = 2.0 | 4000, 5000, 6000, 7000, 8000 | 0.55, 0.60, …, 1.00 |
| `md_planar_morse/` | V(3) | Morse, D_0 = 1, α = 3, r_0 = 1 | 8000 | 0.55, 0.60, …, 1.00 |
| `md_planar_harmonic/` | V(4) | κ (x_c − x)² Θ(x_c − x) + g x, κ = 100, x_c = 1, g = 0.01 | 8000 | 0.55, 0.60, …, 1.00 |

with the LJ 9–3 wall V(x) = ε_w [ (2/15)(σ_w/x)⁹ − (σ_w/x)³ ]. The LJ and Morse walls are truncated and shifted at 10σ from the wall (`src/libs/cdft_1d/external_potentials.py`).

The five profiles of `md_planar_wn2/` at T = 0.55, 0.65, 0.75, 0.85, 0.95 are the training set; all the other profiles are used for validation only.

Each profile is `md_planar_<wall>/N<N>/T_<T>/z_profile.csv` with columns

| column | meaning |
|---|---|
| `x` | distance from the wall, at the centres of the cells of the uniform grid used by all the planar scripts: Δx = 0.2, x = 0.1, 0.3, …, 59.9 (300 rows) |
| `rho` | time-averaged MD number density in the cell |

The MD histograms were binned at Δx = 0.1 or 0.2; the 0.1 bins are averaged in pairs onto the 0.2 cells.

### Droplets

Time-averaged MD density fields of sessile droplets, binned in cylindrical coordinates about the droplet axis, with the wall (LJ 9–3) at z = 0:

| Folder | Series | Wall | N | T |
|---|---|---|---|---|
| `md_drop_wn2/` | D1 | V(1) | ≈ 4.5 × 10⁴ | 0.55, 0.60, …, 0.90 |
| `md_drop_wc_2/` | D2 | V(2) | ≈ 4.5 × 10⁴ | 0.55, 0.60, …, 0.90 |
| `md_drop_wc_1/` | D3 | V(2) | ≈ 2.5 × 10⁴ | 0.55, 0.60, …, 0.70 are used (at higher T the droplet evaporates) |

`rho_field_T<T>.csv` has columns `r, z, rho` on the cell centres of the 300 × 300 mesh of the 3D solver, covering [0, 60] × [0, 60] with Δr = Δz = 0.2 (rows ordered by z, then r).

`cap_fit.csv` (D1 and D2) holds, per temperature, the number of particles `N` of the droplet field, the radius `Lr` and height `Lz` of the cylindrical region, and the spherical-cap fit of the MD field: contact angle `theta_md` and its standard error `sigma_md` from block averaging over the trajectory (degrees), cap radius `R_md`.

### Trained functional

`data/ml_model/ml_dicts/` holds the weights of the three learned corrections of the paper: the pair-correlation correction `dnn_g_fn.dict` (MLP of (r, 1/T)), the repulsive equation-of-state correction `dnn_rep_fn.dict` (MLP of the local packing fraction and 1/T) and the weighted-density kernel `wda_fn.dict` (100 Fourier modes). Steps 2–5, 7 and 8 use these weights; step 6 retrains them.

## Step 2 — Pickles, and planar profiles

```bash
cd src
python preprocess_data.py                # all four walls (or --wall wn2 | wc | morse | harmonic)
```

For every wall, writes to `data/dataset/pkl/profiles_wl_<wall>/`:

- `z_profiles.pkl` — the MD profiles, indexed by (N, T)
- `z_profiles_0.pkl` — the mean-field profiles at the same (N, T) (Euler–Lagrange solution of the baseline functional, starting from the MD profile); they are only drawn for comparison in the training plots

About 30 minutes for the 80 profiles on a GPU (the mean-field solves); `--wall wn2`, the only wall needed for training, takes about 4 minutes.

**Planar profiles with the trained functional.** Set `WALL` (`"wn2"`, `"wc"`, `"morse"` or `"harmonic"`) at the top of `eval_planar.py` and run

```bash
python eval_planar.py
```

For every MD state of the wall it solves the canonical Euler–Lagrange equation with the learned functional and with the mean-field baseline (damped Picard, then Newton, starting from the MD profile) and writes

- `data/dataset/pkl/profiles_wl_<wall>/eval_profiles_wl_<wall>.pkl` — the profiles
- `output/plot_eval_planar_<wall>/eps_rho_<wall>.csv` — per state: the mean absolute density error `eps = (1/L) ∫ |ρ − ρ_MD| dx` and the relative L2 error `rel_l2 = ‖ρ − ρ_MD‖₂ / ‖ρ_MD‖₂`, for the learned functional (`_nn`) and the mean field (`_mf`)
- `output/plot_eval_planar_<wall>/rho_N<N>_T<T>.png` (one per state) and `eps_rho_<wall>.png`

About 30 s per state on a GPU (the 50 states of V(2) take about 25 minutes). Expected relative L2 error of the learned functional (mean field in brackets):

| Wall | states | mean rel-L2 | T ≤ 0.95 | largest |
|---|---|---|---|---|
| V(1) | 10 | 0.014 (0.33) | 0.007 | 0.081 at T = 1.0 |
| V(2) | 50 | 0.022 (0.28) | 0.017 | 0.10 at T = 1.0 |
| V(3) | 10 | 0.032 (0.34) | 0.024 | 0.11 at T = 1.0 |
| V(4) | 10 | 0.022 (0.23) | 0.020 | 0.033 |

## Step 3 — Bulk coexistence and critical point

```bash
python compute_bulk_tmd.py
```

Needs only the trained weights. Solves μ(ρ_l, T) = μ(ρ_v, T), p(ρ_l, T) = p(ρ_v, T) for the learned functional and for the mean-field baseline, and the critical point ∂p/∂ρ = ∂²p/∂ρ² = 0. Writes

- `output/bulk_tmd/phase_curve.{png,svg}` — binodals of both functionals with the MD binodal (Vrabec et al.)
- `output/bulk_tmd/critical_point.txt`
- `data/dataset/pkl/bulk_tmd/pc_nn_operative.pkl` (learned functional, T = 0.55, …, 1.00; read by step 4), `pc_0_operative.pkl` (mean field), `pc_md_operative.pkl` (MD)

A couple of minutes. Expected: T_c = 1.048, ρ_c = 0.291 for the learned functional (MD: T_c = 1.078, ρ_c = 0.317); T_c = 1.005, ρ_c = 0.267 for the mean field.

## Step 4 — Liquid–vapour surface tension

```bash
python lg_continuation.py     # free planar liquid-vapour interfaces
python compute_gamma_lg.py    # needs step 3
```

`lg_continuation.py` computes, for T = 0.55, …, 1.00, a planar liquid slab in coexistence with its vapour (domain of length 60, no wall), starting from a slab at the coexistence densities of the functional, and writes `data/dataset/pkl/profiles_lg/isotherm_profiles_lg_lg.pkl` and the plots `output/plot_lg_isotherm/`.

`compute_gamma_lg.py` integrates the excess grand-potential density across the two interfaces, γ_lv = ½ ∫ (ω(x) − ω_b) dx, and writes

- `data/dataset/pkl/bulk_tmd/pc_md_operative_with_gamma.pkl` — ρ_v, ρ_l and γ_lv of the learned functional per T (read by step 8)
- `output/plot_lg_isotherm/gamma_lg/gamma_lg_cdf_vs_md_N8000.png` — γ_lv(T) against the MD values of Stephan et al., and `gamma_curve_N8000.png`, `gamma_profile_N8000_T<T>.png`

Expected: γ_lv within 1 % of MD on average over T = 0.65–1.0 (0.4–2.3 % per temperature).

## Step 5 — Three-dimensional droplets

```bash
python compute_droplets_3d.py
```

Solves the canonical Euler–Lagrange equation of the learned functional directly in cylindrical coordinates (r, z), with axial symmetry, at the N and T of each MD droplet of D1, D2 and D3 (20 states), with the parameters calibrated on planar profiles and no retraining. The planar kernels are converted to their radial form by Abel inversion (`libs/cdft_axisym/kernels.py`), and the pair convolutions are applied on the 300 × 300 cell-centred mesh with the exact annular cell volumes (`libs/cdft_axisym/convolution.py`). The fixed point ρ = N e^{−β(V_ext + μ_ex[ρ])} / ∫ e^{−β(V_ext + μ_ex[ρ])} dV is iterated with damped Picard mixing followed by Anderson acceleration, starting from the MD field. Writes

- `data/dataset/pkl/droplets_3d/droplets_3d.pkl` — per (series, T): MD and cDFT fields and the relative L1 error ε = ∫ |ρ − ρ_MD| dV / N
- `output/plot_droplets_3d/rho_<set>_T<T>.png` — MD field, cDFT field and their difference
- `output/plot_droplets_3d/eps_rho_droplets.{csv,png}` — ε(T) for the three series

The assembly of the convolution operators takes about 10 minutes and a few GB of memory (CPU, multi-threaded); each droplet then takes about a minute on a GPU (much longer on a CPU). Expected ε: 0.03–0.13 over the 20 states (D1 0.07–0.13, D2 0.03–0.10, D3 0.04–0.09).

## Step 6 — Training from scratch

```bash
python preprocess_data.py --wall wn2    # if step 2 was not run
python adj_train.py
```

Trains the three corrections on the five training profiles of V(1) by adjoint optimisation: at every step the canonical Euler–Lagrange equation is solved to max|residual| ≤ 10⁻¹¹, the loss between the solution and the MD profile is evaluated, and its gradient with respect to the network parameters is obtained from one adjoint (linear) solve. The loss is a multi-bandwidth maximum mean discrepancy, MMD²(ρ, ρ_MD) = (ρ − ρ_MD)ᵀ G (ρ − ρ_MD) with G a sum of Gaussian kernels of widths 0.01 and 0.5, 1.0, …, 5.0, normalised per state by MMD²(0, ρ_MD) and averaged over the five states (`libs/ml/loss.py`).

The schedule, set at the top of `adj_train.py`, is the one of the published weights:

- stage `smooth`: repulsive and pair-correlation corrections, weighted-density kernel switched off; Adam at learning rates 3·10⁻³ (150 steps) then 10⁻³ (130 steps)
- stage `wda`: all three corrections; 10⁻³ (4000 steps), 3·10⁻⁴ (4000), 10⁻⁴ (1350)
- a fresh Adam optimiser at every learning rate, gradients clipped to norm 1; if the loss exceeds five times the best one, the parameters go back to the best ones and the learning rate is halved
- warm start: each step starts Newton from the previous step's solution, and falls back to damped Picard from the MD profile followed by Newton if that fails. Newton converges to the same equilibrium profile as a start from the MD profile, so the loss and gradients are the same; `warm_start = 0` starts every step from the MD profile

The best parameters are written to `data/ml_model/ml_dicts/` (**this overwrites the shipped weights**: copy them first if you want to keep them, or set `SAVE_MODEL = 0`), per-stage copies to `data/ml_model/intermediate_models/` with `SAVE_INTERMEDIATE_MODELS = 1`, and the loss history and the training profiles to `output/plot_train/`. Other settings: `RESTART_ML_MODEL = 1` loads the weights in `ml_dicts/` and runs the `wda` stage only; `TRAIN_DNN`, `TRAIN_DNN_REP`, `TRAIN_WDA` select the corrections to train.

About 9,600 steps, 4–5 hours on one GPU (RTX 6000 Ada).

**Reproducibility.** The seed is fixed and the initial weights are those of the published run: the first loss is 9.24805·10⁻², the same as in the published run to six digits. Over thousands of steps, round-off differences between machines and library versions (and the non-deterministic order of floating-point reductions on GPUs) accumulate, so a retrained model is not bit-identical to the shipped one; it agrees with it to about 1 % in the scores below. To score a retrained model, run steps 2 and 3 with the new weights:

| score | shipped weights |
|---|---|
| mean rel-L2, 5 training states (V(1)) | 0.0065 |
| mean rel-L2, V(1), T = 0.60, 0.70, 0.80, 0.90 | 0.0075 |
| rel-L2, V(1), T = 1.0 | 0.081 |
| mean rel-L2, V(2), N = 8000, training temperatures | 0.018 |
| T_c | 1.048 |

## Step 7 — Wall–liquid adsorption isotherms

```bash
python adsorption_continuation.py              # WALL = "wc" or "wn2" at the top
T_VALS=0.55 python adsorption_continuation.py  # one temperature (e.g. one process per GPU)
```

Starting from an almost empty wall, the particle number is increased by pseudo-arc-length continuation in the canonical ensemble until the adsorbed film is about 30σ thick (N from ≈ 0 to 12000 per 20 × 20 wall area, planar mesh L = 60, Δx = 0.2), at T = 0.55, 0.60, …, 1.00. Every frame stores ρ(x), the grand-potential density ω(x) and the chemical potential. Writes `data/dataset/pkl/profiles_wl_<wall>/isotherm_profiles_wl_<wall>.pkl` (with `T_VALS`: `isotherm_profiles_wl_<wall>_T<T>.pkl`) and `output/plot_adsorption_wl_<wall>/`.

This is the most expensive step: about an hour per temperature and wall on a GPU. Running the temperatures in parallel with `T_VALS` is recommended.

## Step 8 — Binding potential and contact angles

```bash
python compute_contact_angle.py   # WALL = "wc" or "wn2" at the top; needs steps 4 and 7
```

1. For every frame of the isotherms of step 7: the work of adsorption W = ∫ (ω(x) − ω_b) dx and the film thickness l from the adsorbed excess; then piecewise-linear regressors of W(l) and μ₀(l), saved as TorchScript modules in `data/dataset/pkl/profiles_wl_<wall>/{work,mu0}_regressor_wl_<wall>/` (plots in `output/plot_adsorption_work_wl_<wall>/`).
2. Surface tensions γ_wl = W_∞ − γ_lv (W_∞ the thick-film plateau of W(l)) and γ_wv = W at the wall–vapour state of the isotherm; Young angle cos θ_Y = (γ_wv − γ_wl)/γ_lv.
3. For each MD droplet of the wall (D1 for `wn2`, D2 for `wc`), minimisation of the excess free energy ΔF(𝓡, ϑ) of a spherical cap at the droplet's N, with the cap radius fixed by the volume constraint, giving the apparent contact angle θ_c; comparison with the MD angle of `cap_fit.csv`.
4. Free-energy landscapes ΔF(ϑ) at fixed N, and θ_c as a function of T and N.

Writes to `output/plot_contact_angle_<wall>/`: `theta_c.csv` and `theta_vs_T.png` (θ_c, θ_Y and θ_MD with 3σ error bars), `gammas_vs_T.png`, `thetaY_vs_T.png`, `drop/Drop_T<T>.png` (MD field with the predicted cap), `dF_landscape.png`, `theta_vs_T_N.png` and `theta_c_T_N.csv`, `sanitycheck/`. A few minutes on a CPU.

Expected mean absolute deviation of θ_c from the MD angle over T = 0.55–0.90: 2.4° on V(1), 3.0° on V(2). On V(2), γ_wl + γ_lv = γ_wv (wetting) between T = 0.85 and 0.90.

## Troubleshooting

- **`ModuleNotFoundError: No module named 'libs'`** — run the scripts from `src/`.
- **`FileNotFoundError` for `z_profiles.pkl`** — run `preprocess_data.py` (step 2).
- **`FileNotFoundError` for `pc_nn_operative.pkl`** — run `compute_bulk_tmd.py` (step 3) before `compute_gamma_lg.py`.
- **`FileNotFoundError` for `pc_md_operative_with_gamma.pkl`** — run step 4 before `compute_contact_angle.py`.
- **`No isotherm pickle matches ...`** — run `adsorption_continuation.py` with the same `WALL` before `compute_contact_angle.py`.
- **CUDA out of memory** — use another GPU (`CUDA_VISIBLE_DEVICES`) or `TORCH_DEVICE=cpu`.
- **Apple MPS** — MPS does not support float64, which `eval_planar.py`, `compute_bulk_tmd.py`, `compute_droplets_3d.py`, `adj_train.py` and `adsorption_continuation.py` use: run them on CUDA or CPU (`TORCH_DEVICE=cpu`).
